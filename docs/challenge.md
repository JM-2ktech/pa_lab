> **이번 챌린지 완성물**: 2026-09 점검에서 「이상」 판정이 난 설비마다 조치 확인 승인을 따로 받고, 응답을 한 장의 표로 모아 메일로 받는 인스턴트 흐름 `이상조치 확인_HGD`
>
> **예상 시간**: 30~40분
>
> **완성 신호**: 승인 요청 2건에 응답한 뒤 `HGD [조치 확인 결과] 2026-09` 메일이 오고, 표에 2행이 있다

선택 과제입니다. Lab 1~3을 마친 뒤 진행합니다. 스텝 안내 없이 아래 요구사항만으로 만듭니다.

---

## 상황

Lab 3의 월간 보고서 승인은 보고서 한 건을 통째로 승인합니다. 현장에서는 「이상」 판정이 난 설비마다 담당자가 조치를 끝냈는지 따로 확인받아야 합니다. 확인 결과는 한 장의 표로 모아 메일로 받습니다.

## 목표

- 같은 승인을 대상 건수만큼 반복해서 보냅니다.
- 반복할 때마다 나온 결과를 변수에 모아 두었다가, 반복이 끝난 뒤 한 번에 씁니다.

## 요구사항

1. 인스턴트 흐름 `이상조치 확인_HGD` 를 새로 만듭니다. `HGD` 는 본인 이니셜입니다. Lab 2 · 3의 `월간 점검보고서_HGD` 는 건드리지 않습니다.
2. Lab 2와 같은 점검 기록에서 대상월(지난달, `2026-09`)의 행 가운데 결과가 `이상` 인 행만 고릅니다.
3. 고른 행마다 승인 요청을 하나씩 보냅니다.
    - 승인 형식은 Lab 3과 같은 「승인/거부 - 첫 번째로 응답」입니다.
    - 제목: `HGD 이상조치 확인 — ` 뒤에 설비명
    - 세부 정보: 구역 · 점검항목 · 측정값 · 조치내용
    - 할당 대상: 본인 교육 계정
4. 응답이 올 때마다 설비명 · 응답 결과(`Approve` / `Reject`) · 의견을 한 줄씩 모읍니다.
5. 반복이 끝나면 모은 줄을 HTML 표로 만들어 본인에게 메일로 보냅니다.
    - 제목: `HGD [조치 확인 결과] 2026-09`
6. 실행할 때 승인 두 건 가운데 한 건은 승인, 한 건은 의견을 적고 거부합니다.

## 쓰는 기능

| 기능 | 처음 나오는가 | 참고 |
|---|---|---|
| Excel 표 행 나열 · 배열 필터링 · 대상월 식 | 아니요 | Lab 2 |
| 승인 시작 및 대기 · 반려 의견 식 | 아니요 | Lab 3 |
| HTML 테이블 만들기 · 메일 보내기(V2) | 아니요 | Lab 2 |
| 각각에 적용 (컨트롤) | 예 | 반복 |
| 변수 초기화 · 배열 변수에 추가 | 예 | 결과 모으기 |

{: .warning }
**Lab 2 · 3의 카드를 복사해 붙여넣을 때 카드 이름을 확인합니다.** 이름 끝에 ` 1` 이 붙으면 그 이름을 부르는 식이 카드를 찾지 못합니다.

## 확인

**필수**: 여기까지 되면 챌린지 통과입니다

- ① 승인 요청이 2건 온다 (2026-09 「이상」 2건)
- ② 결과 메일의 표가 2행이고, 각 행에 설비명 · Approve 또는 Reject · 의견이 있다
- ③ 거부한 행의 의견 칸에 입력한 문장이 그대로 있다
{: .checklist }

**관찰**: 나오면 좋고, 안 나와도 실패가 아닙니다

- ④ 두 번째 승인 요청은 첫 번째에 응답한 뒤에 온다 — 반복은 기본적으로 한 건씩 차례로 돈다
- ⑤ 반복의 설정에서 동시성 제어를 찾아본다. 켜면 요청이 한꺼번에 오지만, 배열 변수에 쓰는 순서가 섞일 수 있다[^variables]
{: .checklist }

**더 해 보기**

- 거부된 건만 골라 Teams 흐름 봇으로 따로 알립니다.
- 「주의」 3건까지 대상에 넣습니다.

[^variables]: **Store and manage values in variables** — Microsoft Learn. <https://learn.microsoft.com/ko-kr/power-automate/create-variable-store-values> (2026-10-06 확인). 변수 초기화 · 배열 변수에 추가. 각각에 적용은 기본이 순차 실행이고, 반복 안에서 변수를 쓰면 결과가 예측 가능하도록 순차로 둬야 한다. 변수는 반복 안에서 초기화할 수 없다.
