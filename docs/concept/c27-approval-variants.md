## 승인 형식

**승인 시작 및 대기**의 첫 칸에서 고릅니다.[^allmust]

| 영어 이름 | 한국어판 표기 | 완료 조건 |
|---|---|---|
| Approve/Reject - First to respond | 승인/거부 - 첫 번째로 응답 | 한 명의 승인 또는 거부 |
| Approve/Reject - Everyone must approve | 승인/거부 - 모두가 승인해야 함 | 전원 승인 또는 한 명의 거부 |
| Custom responses - Wait for one response | 사용자 지정 응답 - 한 개 응답 대기 | 한 명의 응답 |
| Custom responses - Wait for all responses | 사용자 지정 응답 - 모든 응답 대기 | 전원의 응답 |

응답하는 곳과 첫 실행 프로비저닝은 [C15](c15-approvals.html)에 있습니다.

## 변형 비교

순차와 병렬은 승인 형식이 아닌 흐름 구성입니다. 승인 작업을 어떻게 잇느냐로 만듭니다.

| 변형 | 언제 쓰는가 | 설정과 구성 | 다음 작업이 실행되는 때 | 결과 처리 |
|---|---|---|---|---|
| 첫 번째 응답 | 담당자 중 한 명만 결정하면 되는 요청 | 승인 작업 1개. 형식 첫 번째로 응답 | 한 명이 결정한 뒤 | 조건에서 결과가 `Approve` 인지 비교 |
| 전원 승인[^allmust] | 관리자와 상위 관리자가 모두 동의해야 하고 한 명이 반려할 수 있는 요청 | 승인 작업 1개. 형식 모두가 승인해야 함. 할당 대상에 여러 명 | 전원이 승인하거나 한 명이 거부한 뒤 | 조건에서 결과 비교. 실행 기록에서 값 확인 |
| 순차[^seq] | 사전 승인을 거쳐 최종 승인으로 가는 요청. 예: 일정 금액을 넘는 청구서 | 승인 작업을 위아래로 2개 이상. 앞 승인의 조건 True 갈래에 다음 승인 배치 | 각 승인의 응답 뒤. 사전 승인되어야 최종 승인자에게 감 | 승인마다 조건 하나 |
| 병렬[^par] | 부서마다 독립적으로 결정하는 요청. 예: 관리자 · 영업팀 · 인사팀 | 병렬 분기마다 승인 작업 1개. 형식은 분기마다 지정 | 분기 안 작업은 그 분기의 응답 뒤. 분기 아래 작업은 모든 분기가 끝난 뒤 | 분기마다 조건 하나 |
| 사용자 지정 응답 · 한 명[^custom] | 승인 · 거부 외의 선택지가 필요한 요청. 예: 수락 · 추가 정보 필요 · 거부 | 승인 작업 1개. 응답 옵션 항목 입력 | 한 명이 응답한 뒤 | 조건이나 Switch에서 결과를 옵션 글자와 비교 |
| 사용자 지정 응답 · 전원[^allmust] | 각자의 선택을 모두 받아야 하는 요청 | 승인 작업 1개. 응답 옵션 항목 입력. 할당 대상에 여러 명 | 전원이 응답한 뒤 | 응답 목록을 항목마다 확인 |
| 텍스트 승인[^conn] | 승인자가 제안 문구를 고쳐서 답하는 요청 | 별도 작업 Start and wait for an approval of text. 제목 · 제안 텍스트 칸 | 승인 완료 뒤 | 수락된 텍스트(`acceptedText`) 출력 사용 |
| 만들기와 대기 분리[^conn] | 요청과 대기 사이에 다른 작업을 둘 때 | 별도 작업 Create an approval · Wait for an approval | 대기 작업이 응답을 받은 뒤 | 두 작업을 붙여 둠. 알려진 문제 표 참고 |

순차와 병렬의 예제 문서는 할당 대상을 **관리자 가져오기(V2)**의 메일로 채웁니다. Office 365 Users 커넥터 작업입니다.

## 결과 값과 응답

| 형식 | 결과(Outcome) 값 | 조건 |
|---|---|---|
| 승인/거부 | `Approve` · `Reject` | 대소문자 구분. 화면 언어와 무관[^conn] |
| 사용자 지정 응답 | 응답 옵션 항목에 적은 글자 | 옵션마다 비교 |

전원 승인의 결과를 한 문서는 응답 수만큼의 `Approve` · `Reject` 배열로 적고[^allmust], 커넥터 참조는 유효한 응답을 `Approve` · `Reject` 로 적습니다.[^conn] 조건을 걸기 전에 실행 기록에서 **결과** 출력을 확인합니다.

## 작업의 칸

| 칸 | 필수 | 내용 |
|---|:---:|---|
| 승인 형식 | 예 | 위 표의 네 가지 |
| 제목 | 예 | 요청 제목 |
| 할당 대상 | 예 | 메일 주소 · UPN · Microsoft Entra ID 사용자 ID. 여러 명은 `;` 로 구분하고 형식을 섞을 수 있음 |
| 세부 정보 | | Markdown 지원 |
| 항목 링크 | | 승인 대상 URL |
| 항목 링크 설명 | | 링크에 보이는 글자 |
| 요청자 | | 요청을 만든 사람의 메일 |
| 알림 사용 | | 메일 · 푸시 · Teams 알림 |
| 재할당 사용 | | 다른 사람에게 재할당 허용 |
| 첨부 파일 | | 이름이 중복되면 승인을 만들 수 없음 |

할당 대상에 여러 형식을 섞은 예입니다.[^conn]

```

```

## 사용자 지정 응답의 제한

- Outlook · Outlook 웹의 실행 가능 메시지에는 처음 5개 옵션만 보입니다. 나머지는 승인 센터 · 모바일 앱 · Teams · HTML 메일에서 고릅니다.[^custom]
- 옵션이 1개면 Outlook에서 단추 없이 입력 칸이 바로 펼쳐집니다.
- 많은 사용자에게 모두 승인해야 함 형식으로 보내면 결과 필드의 크기 제한으로 실패할 수 있습니다.

## 세부 정보의 Markdown

클라이언트마다 지원이 다릅니다.[^md]

| 기능 | Power Automate | 모바일 앱 | Outlook | Outlook 웹 | Teams | Teams 모바일 | Teams 승인 앱 |
|---|:---:|:---:|:---:|:---:|:---:|:---:|:---:|
| 제목 | 예 | 예 | 예 | 예 | 아니요 | 아니요 | 아니요 |
| 번호 목록 | 예 | 예 | 아니요 | 예 | 예 | 예 | 아니요 |
| 중첩 번호 목록 | 예 | 예 | 아니요 | 예 | 예 | 예 | 예 |
| 표 | 예 | 예 | 예 | 예 | 아니요 | 아니요 | 아니요 |
| 이미지 | 아니요 | 아니요 | 아니요 | 아니요 | 아니요 | 아니요 | 아니요 |
| 강제 줄바꿈 | 예 | 예 | 아니요 | 예 | 예 | 예 | 아니요 |
| 빈 줄 | 아니요 | 아니요 | 예 | 예 | 아니요 | 예 | 아니요 |
| 강조 | 예 | 예 | 예 | 예 | 아니요 | 아니요 | 아니요 |

문서 머리말은 Teams 승인 앱에서 Markdown을 지원하지 않는다고 적습니다. 2026-10-05 실측에서 불릿 목록은 Teams 승인 앱에 목록으로 보였습니다. 쓸 클라이언트에서 직접 확인합니다.

| 표기 | 쓰는 법 |
|---|---|
| 제목 | 줄 앞에 `#` ~ `######` |
| 번호 목록 | `1. 항목` |
| 불릿 목록 | `- 항목` |
| 강제 줄바꿈 | 줄 끝에 공백 두 칸. Outlook은 빈 줄을 사용 |
| 링크 | `[글자](https://주소)`. HTTPS만 모든 클라이언트에서 링크가 됨 |
| 굵게 · 기울임 · 취소선 | `**글자**` · `_글자_` · `~~글자~~` |
| 특수 문자 | 앞에 `\` |

표는 머리글 줄과 구분 줄로 시작하고 행마다 줄을 바꿉니다. 칸 안 정렬은 지원하지 않습니다.

```
| 항목 | 값 |
|-----------|-----------|
| 대상월 | 2026-09 |
```

## 알려진 문제

| 문제 | 내용 | 대응 |
|---|---|---|
| 게스트 승인자[^known] | 유효한 라이선스가 있어야 보고 응답함. 초대를 수락하지 않은 게스트는 할당 대상에서 제외됨. 전원이 미수락이면 승인 생성 실패 | 초대 수락 확인 후 할당 |
| Teams 카드 불일치 | 메일이나 승인 센터에서 응답해도 Teams의 적응형 카드가 갱신되지 않음 | 승인 작업의 기본 메일 알림 끄기 |
| 버려진 승인 | 대기가 28일을 넘으면 흐름은 실패하고 승인은 승인 센터에 남음 | 요청자나 환경 관리자가 직접 삭제 |
| 앵커 링크 | 지원하지 않음 | 쓰지 않음 |
| 데이터 템플릿 | 적응형 카드의 템플릿을 완전히 지원하지 않음 | 작성 · 필터 · 선택 · 각각에 적용으로 카드 구성 |
| 사용자 지정 응답과 전원 승인 | 많은 사용자에게 보내면 실패 | 대상 수 줄이기 |
| 만들기와 대기 분리 | 대기 작업 전에 응답하면 대기에서 멈춤 | 두 작업을 붙여 둠 |
| Do until 안의 승인 | 모든 결과를 처리하지 않으면 무한 반복. 최종 상태는 승인 · 거부 · 취소 | 조건이나 Switch 사용 |
| 받음 탭의 세부 정보 | 세부 정보 열이 사라짐 | 요청을 열어 확인 |
| 승인 메일 회신 | 받는 사람이 자동으로 채워지지 않음 | 직접 입력 |
| 시각 표시[^conn] | 승인의 타임스탬프는 항상 UTC | 표시 값 변환. [C11](c11-datetime.html) |
| 작성자 표시 | 세부 정보에 흐름 작성자가 항상 보임. 보낸 사람 위장 방지 | 없음 |
| 보낸 주소 | 승인 메일은 표준 계정에서만 응답 단추가 동작 | 직접 만든 메일에는 승인 링크만 넣음 |
| 호출 한도 | 흐름당 승인 만들기 60초에 50건, 그 외 500건 | [C25](c25-throttling.html) |

승인 알림 메일의 상태입니다.[^known]

| 상태 | 뜻 | 조치 |
|---|---|---|
| Pending | 발송을 요청 중 | 대기 |
| Requested | 요청이 접수되어 처리 중 | 대기 |
| Sent | 발송 완료 | 메일이 없으면 받은 편지함 새로 고침 · 주소 · 필터 · 스팸 폴더 확인 |
| Failed | 큐에 들어간 뒤 발송 오류 | 같은 받는 사람에게 다시 요청. 안 되면 Microsoft 지원 |

## 샘플

사용자 지정 응답으로 승인을 보내고 고른 글자를 결과로 받습니다.

1. [Power Automate — {{ site.pa.environment }}]({{ site.pa.powerautomate_url }}){:target="_blank"}를 엽니다. 왼쪽 메뉴 **+ 만들기**를 누르고 **시작(처음부터)**의 **인스턴트 클라우드 흐름**을 고릅니다.
2. **흐름 이름**에 아래를 입력하고 트리거 목록에서 **수동으로 흐름 트리거**를 고른 뒤 **만들기**를 누릅니다. `HGD` 대신 본인 이니셜을 넣습니다.

    ```
    승인 변형_HGD
    ```

3. 트리거 카드 아래 **+** › **작업 추가**에서 `표준 승인` 을 검색합니다. **승인 시작 및 대기** 두 개 중 구성 창의 첫 칸이 **승인 형식**인 작업을 고릅니다.
4. **승인 형식**에서 **사용자 지정 응답 - 한 개 응답 대기**를 고릅니다.
5. **응답 옵션 항목**에 아래를 입력합니다.

    ```
    수락
    ```

6. **새 항목 추가**를 누르고 아래를 입력합니다.

    ```
    거부
    ```

7. **새 항목 추가**를 누르고 아래를 입력합니다.

    ```
    추가 정보 필요
    ```

8. **제목**에 아래를 입력합니다.

    ```
    HGD 승인 변형 연습
    ```

9. **할당 대상** 칸에 `edu` 를 입력하고 목록에서 **교육**을 고릅니다.
10. **승인 시작 및 대기** 아래 **+** › **작업 추가**에서 `작성` 을 검색해 **작성**을 고릅니다. **입력** 칸의 번개 단추를 누르고 **승인 시작 및 대기** 아래 **결과**를 고릅니다. 목록에 없으면 **더 보기**를 누릅니다.
11. **저장**을 누르고 **테스트** › **수동** › **테스트**를 누릅니다. **흐름 실행**을 누르고 **완료**를 누릅니다.
12. Teams를 열고 **활동**에서 `HGD 승인 변형 연습` 알림을 누릅니다. **승인** 앱의 **받음** 탭에서 요청을 엽니다.

    **완료 기준**: 응답 선택지에 수락 · 거부 · 추가 정보 필요가 보인다.

13. **추가 정보 필요**를 골라 응답합니다.
14. Power Automate 탭으로 돌아가 실행 화면의 **작성** 카드를 누릅니다.

    **완료 기준**: 출력이 `추가 정보 필요` 이다.

[^custom]: **Create custom response options for approval flows** — Microsoft Learn. <https://learn.microsoft.com/ko-kr/power-automate/create-approval-response-options> (2026-11-02 확인). 응답 옵션 항목, 조건과 Switch, Outlook 5개 제한.
[^md]: **Use Markdown language in Power Automate approval requests** — Microsoft Learn. <https://learn.microsoft.com/ko-kr/power-automate/approvals-markdown-support> (2026-11-02 영어판 확인). 클라이언트별 지원 표와 표기.
[^known]: **Known issues** — Microsoft Learn. <https://learn.microsoft.com/ko-kr/power-automate/approvals-known-issues> (2026-11-02 영어판 확인). 게스트, Teams 카드, 28일 대기, 분리 작업, 반복 안의 승인, 메일 상태.
[^conn]: **Standard approvals** — Microsoft Learn 커넥터 참조. <https://learn.microsoft.com/ko-kr/connectors/approvals/> (2026-11-02 영어판 확인). 응답 값의 대소문자, 할당 대상 형식, 텍스트 승인과 분리 작업, 타임스탬프, 표준 계정, 호출 한도.
