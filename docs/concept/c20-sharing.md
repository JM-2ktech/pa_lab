> **다루는 것**: 클라우드 흐름을 다른 사람과 공유하는 세 방법, 소유자와 실행 전용 사용자의 권한, 연결의 주인, 소유자 변경
>
> **쓰는 곳**: 랩에서 쓰지 않음

## 공유하는 세 방법

클라우드 흐름을 공유하는 방법은 세 가지입니다.[^share]

| 방법 | 받는 사람이 하는 일 | 연결 | 고치면 | 쓰는 경우 |
|---|---|---|---|---|
| 소유자 추가 | 보기 · 편집 · 실행 · 공유 · 삭제 | 흐름에 정의된 연결 | 같은 흐름이 바뀜 | 함께 만들고 유지 |
| 실행 전용 | 실행만 | 흐름의 연결 또는 실행자 연결 | 받는 사람은 고칠 수 없음 | 여러 사람이 쓰는 인스턴트 흐름 |
| 복사본 보내기 | 자기 흐름을 새로 만듦 | 공유되지 않음. 받는 사람이 다시 연결 | 서로 영향 없음 | 구조만 나눠 줌 |

- 공유하려면 무료 라이선스를 뺀 Power Automate 라이선스나 Office 365 같은 포함 라이선스가 있어야 합니다.
- 소유자를 추가하거나 제거하려면 작성자나 소유자여야 합니다.
- 사용자 대신 그룹을 지정할 수 있습니다.
- 복사본은 보낸 뒤에 접근을 취소할 수 없습니다.

## 소유자와 실행 전용 사용자의 권한

둘의 권한을 견준 표입니다.[^guide][^notify]

| 권한 | 소유자 | 실행 전용 사용자 |
|---|---|---|
| 정의 보기 · 편집 | 가능 | 불가 |
| 실행 | 가능 | 가능. 소유자가 허용한 트리거로 |
| 실행 기록 보기 | 가능 | 불가 |
| 켜기 · 끄기 · 이름 변경 · 삭제 | 가능 | 불가 |
| 다른 사람에게 공유 | 가능. 작성자는 제거할 수 없음 | 불가 |
| 연결 | 흐름의 연결을 씀. 다른 소유자가 만든 연결의 자격 증명은 고칠 수 없음 | 설정에 따라 다름 |
| 화면에서 보이는 곳 | **팀 흐름** 탭 | 실행할 수 있는 곳(단추 · 앱). 내 흐름 목록에는 없음 |
| 실패 알림 메일 | 받음 | 받지 않음 |

공동 소유자는 작성자와 거의 같은 권한을 가집니다. 공동 작업이 필요할 때만 추가합니다. 나머지 경우에는 실행 전용으로 공유합니다.[^access]

## 소유자 추가와 실행 전용 설정

조작 위치입니다.[^share]

| 작업 | 위치 |
|---|---|
| 소유자 추가 | **내 흐름** › 흐름의 **⋮** › **공유** › 이름 · 메일 · 그룹 입력 |
| 소유자 제거 | 흐름 세부 정보 페이지의 소유자 섹션 **편집** › 휴지통 › **제거** |
| 실행 전용 추가 | 세부 정보 페이지의 **실행 전용 사용자** 섹션 **편집** › 사용자 · 그룹 입력 |
| 실행 전용 제거 | 같은 패널의 휴지통 › **저장** |
| 복사본 보내기 | 세부 정보 페이지 명령 모음의 **복사본 보내기** |
| 연결 바꾸기 | **편집** › 해당 단계의 **…** › 기존 연결 선택 또는 **새 연결 추가** › **로그인** |

실행 전용 공유는 수동 트리거를 쓰는 인스턴트 흐름에 씁니다. 단추나 선택한 항목으로 시작하는 흐름입니다.

## 연결의 주인

흐름의 작업은 연결을 통해 서비스에 접속합니다. 그 연결을 만든 계정의 권한으로 실행됩니다.[^share] 연결 자체는 [C3](c03-connectors.html)에서 다룹니다.

| 구분 | 내용 |
|---|---|
| 포함 연결 | 흐름에서 쓰는 연결 |
| 기타 연결 | 흐름에 정의돼 있지만 쓰지 않는 연결. 다시 쓸 때까지 **기타 연결** 목록에 남음 |
| 공유 범위 | 공유한 연결은 그 흐름에서만 쓸 수 있음 |
| 다른 소유자의 연결 | 서비스 사용은 가능. 자격 증명은 고칠 수 없음 |
| 소유자를 제거할 때 | 그 사람의 연결을 쓰던 작업의 연결을 먼저 바꿈 |

실행 전용 공유에서는 소유자가 연결을 고릅니다.[^share]

| 설정 | 누구의 권한으로 실행 | 필요한 것 |
|---|---|---|
| 흐름에 정의된 연결 사용 | 그 연결을 만든 소유자 | 실행자는 단추만 누름 |
| **실행 전용 사용자가 제공** | 실행하는 사람 | 실행자 본인의 연결과 데이터 권한 |

**실행 전용 사용자가 제공** 연결은 제공한 사람만 씁니다. 내보낸 흐름에서는 `RuntimeSource` 값이 `invoker` 입니다.[^share]

## 소유자와 라이선스

흐름 유형에 따라 누구의 라이선스를 쓰는지가 다릅니다.[^owner][^faq]

| 흐름 유형 | 쓰는 라이선스와 작업 수 한도 |
|---|---|
| 자동 · 예약 흐름 | 작성자나 소유자 |
| 인스턴트 흐름 | 실행한 사람 |
| Process 라이선스가 있는 흐름 | 그 라이선스 |
| 서비스 주체가 소유한 흐름 | 비라이선스 사용자 한도 또는 Process 라이선스 |

- 소유자가 조직을 떠나면 흐름의 성능 프로필이 Low 로 내려갑니다.[^limits]
- 프리미엄 커넥터를 쓰는 인스턴트 흐름은 실행한 사람에게 프리미엄 라이선스가 필요합니다.[^errref]
- 예약 · 자동 흐름의 소유자를 바꾸면 새 소유자의 라이선스가 적용되기까지 최대 7일이 걸립니다. 흐름을 편집해 저장하면 바로 적용됩니다.[^owner]

## 소유자를 바꾸는 방법

흐름이 솔루션에 있는지에 따라 방법이 다릅니다.[^share][^owner]

| 흐름 | 방법 | 결과 |
|---|---|---|
| 솔루션 흐름 | 세부 정보의 **편집** › **기본 소유자** 교체 | 이전 소유자와 새 소유자가 공동 소유자가 됨 |
| 비솔루션 흐름 · Dataverse 환경 | 흐름을 솔루션에 넣은 뒤 위 방법 | 같음 |
| 비솔루션 흐름 · Dataverse 없는 환경 | 내보내기와 가져오기 · **다른 이름으로 저장** · **복사본 보내기** | 새 흐름이 생김. 소유자가 흐름 ID 의 일부라 기존 흐름에서 바꿀 수 없음 |

| 만든 사람이 떠났을 때 | 동작 |
|---|---|
| 활성 소유자가 남아 있음 | 흐름은 계속 실행. 떠난 사람의 연결을 쓰던 작업은 실패할 수 있음 |
| 활성 소유자가 없음 | 복사본을 만들어 새 소유자가 흐름을 만듦 |

## 사용자 계정과 서비스 주체

흐름의 소유자는 사용자 계정이나 서비스 주체(SPN)입니다.[^access][^owner]

| 항목 | 서비스 주체 | 사용자 계정 |
|---|---|---|
| 직원 퇴사 영향 | 없음 | 있음 |
| 권한 | 필요한 접근만 부여 | 그 사용자의 권한 |
| 감사 | 특정 사용자와 분리된 기록 | 사용자 기록 |
| 설정 | 애플리케이션 사용자를 만들고 연결을 공유 | 간단 |
| 어울리는 흐름 | 중요하거나 오래 도는 흐름 | 사용자 맥락이나 승인 · 판단이 필요한 흐름 |
| 공동 소유자 | 될 수 없음. 기본 소유자로만 지정 | 가능 |

## 환경의 역할

공유 권한과 별도로 환경 역할이 만들 수 있는 사람을 정합니다.[^guide]

| 역할 | 할 수 있는 일 |
|---|---|
| 환경 관리자 | 환경의 모든 리소스 관리. 모든 흐름을 편집하고 흐르는 데이터를 볼 수 있음 |
| Environment Maker | 흐름 · 앱 · 연결을 만들고 공유. Dataverse 데이터 접근 권한은 없음 |
| 기본 사용자(Basic User) | Dataverse 데이터를 쓰는 앱과 흐름 실행 |

워크플로 테이블에 전체 접근 권한이 있는 사용자도 모든 흐름을 편집하고 실행 기록을 볼 수 있습니다.[^access]

## 공유 규칙을 정할 때

문서가 권하는 운영 기준입니다.[^guide][^share]

| 기준 | 내용 |
|---|---|
| 실행 전용 우선 | 많은 사람이 쓰는 흐름은 실행 전용. 공동 소유자는 편집이 필요할 때만 |
| 그룹으로 관리 | 사람 대신 보안 그룹을 지정. 구성원 변경으로 권한을 관리 |
| 역할 분리 | Environment Maker 는 만드는 사람에게만 |
| 환경 접근 | 보안 그룹으로 환경 구성원을 제한 |
| 데이터 정책 | DLP 로 커넥터 사용을 제한. 공유 자체를 막지는 않음 |
| 정기 점검 | 월 · 분기별로 소유자와 공유 대상을 검토 |
| 환경 밖 사용자 | 복사본을 내보내 그쪽 환경에서 다시 연결 |

SharePoint 목록을 공동 소유자로 추가할 수도 있습니다. 목록 편집 권한이 있는 사람이 흐름 편집 권한도 갖습니다. 흐름이 SharePoint 에 연결돼 있으면 목록을, 그 밖에는 그룹을 씁니다.[^share]
