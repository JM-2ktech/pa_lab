# C22. 오류 코드와 실패 알림

> **다루는 것**: 실패한 클라우드 흐름에서 보이는 오류 코드의 뜻과 조치, 연결이 끊어지는 원인, 실패 알림 메일이 오는 조건
>
> **쓰는 곳**: 랩에서 쓰지 않음

## 실패를 찾는 순서

위에서부터 차례로 확인합니다.[^fixconn]

| 순서 | 확인할 것 | 보는 화면 | 결과에 따른 조치 |
|---:|---|---|---|
| 1 | 흐름이 켜져 있는가 | 흐름 세부 정보의 상태 | 꺼짐: 다시 켬. 일시 중단됨: 실패 원인을 고친 뒤 켬 |
| 2 | 트리거가 실행됐는가 | 28일 실행 기록 | 기록 없음: 아래 표. 전부 취소됨: 트리거 동시성 설정 확인 |
| 3 | 어느 작업이 실패했는가 | 실패한 실행의 빨간 카드 | 입력 · 출력과 오류 코드 확인 |
| 4 | 연결이 정상인가 | 왼쪽 메뉴의 연결 | 경고가 있으면 다시 인증 |

흐름이 목록에 없으면 환경부터 확인합니다.

실행 기록이 없을 때 트리거 유형별 확인 항목입니다.

| 트리거 | 확인할 것 |
|---|---|
| 예약 | 되풀이 설정과 시간대. 9:00은 트리거에 지정한 시간대 기준 |
| 자동화 | 이벤트가 실제로 일어났는지. 시험 항목을 만들고 5~10분 대기 |
| 트리거 조건이 있는 흐름 | 시험 이벤트에서 식이 true인지. [C26](c26-trigger-conditions.html) |
| 인스턴트 | 사용자가 시작해야 실행됨 |

실패한 카드가 여러 개면 실행 기록에서 **첫 번째로 실패한 작업**을 봅니다. 그 뒤의 작업은 앞 작업에 의존해 함께 실패로 표시되는 계단식 오류입니다.[^notify]

실패한 실행 화면에서 쓰는 항목입니다.[^fixflow]

| 항목 | 내용 |
|---|---|
| 입력 | 작업이 실제로 보낸 값. 요청 URL · 행 ID 등 |
| 출력 | 대상 서비스가 돌려준 오류 메시지와 상태 코드 |
| 다시 제출 | 같은 입력으로 다시 실행. 500 · 502 같은 일시적 오류나 흐름을 고친 뒤에 사용 |
| 열 편집 | 실행 기록 목록에 트리거 출력 열을 추가. 자주 도는 흐름에서 실행을 찾을 때 사용 |

## 설계 시 오류

저장 · 유효성 검사 · 게시할 때 나는 오류입니다.[^errors]

| 코드 | 뜻 | 흔한 원인 | 조치 |
|---|---|---|---|
| `InvalidTemplate` | 식이나 작업 구성의 구문 오류 | 괄호 · 따옴표 짝 불일치, 없는 작업 이름 참조, 인수 개수 오류, 상수 식의 형식 오류(`int('abc')` · `div(100, 0)`), 문서에서 복사한 보이지 않는 유니코드 문자 | 빨간 카드의 식 확인. 식을 지우고 직접 입력 |
| `FlowCheckerError` | 흐름 검사기가 저장을 막음 | 필수 칸이 빔, 연결 미선택, 병렬 분기 값 참조, 트리거 입력 미완성 | 오류 배너를 눌러 목록을 보고 항목마다 수정 |
| `DuplicateActionName` | 내부 이름이 같은 작업이 둘 이상 | 복사 후 이름 그대로, 같은 범위의 이름으로 변경, 정의를 직접 수정해 가져옴 | 한쪽 이름 변경. 그 이름을 부르는 식도 수정 |
| `MissingRequiredProperty` | 필수 입력이 비어 있음 | 구성 미완료, 비어 버린 동적 값, 솔루션 가져오기 후 환경 변수 미설정 | 빨간 별표 칸 입력. 솔루션 흐름은 환경 변수 값 확인 |

식 안의 작업 이름은 공백 대신 `_` 를 쓰고 대소문자를 구분합니다. 작업 이름이 `Get item` 이면 식은 아래입니다.

```
outputs('Get_item')
```

## 실행 시 식 오류

실행 중에 식을 계산하지 못할 때 나는 오류입니다. 같은 식이라도 상수만 쓰면 저장할 때 `InvalidTemplate` 로 잡히고, 변수 · 트리거 본문 · 작업 출력을 쓰면 실행할 때 잡힙니다.[^errors]

| 코드 | 뜻 | 흔한 원인 | 조치 |
|---|---|---|---|
| `ExpressionEvaluationFailed` | 실제 데이터가 식이 기대한 모양과 다름 | 숫자가 아닌 문자열에 `int()`, null 객체의 속성 접근, 날짜 형식 불일치, 동적 값 0으로 나눔 | 실패한 작업의 입력 확인. 식 앞에 null 검사와 형식 검사 추가 |
| `ContentConversionFailed` | 작업 사이의 형식 변환 실패 | 정수 · 부울 칸에 문자열, 객체 하나를 받는 칸에 배열, 날짜 형식 불일치, 텍스트 칸에 파일 | `int()` · `float()` · `string()` · `bool()` · `json()` 으로 변환. 날짜는 `parseDateTime()` · `formatDateTime()`. 배열은 `first()` |

null과 형식에 대비하는 식의 모양입니다.

```
coalesce(outputs('Get_item')?['body/title'], 'Untitled')
```

```
if(empty(triggerBody()?['value']), 'default', triggerBody()?['value'])
```

```
if(isInt(variables('input')), int(variables('input')), 0)
```

## 연결과 인증 오류

흐름이 연결된 서비스에 인증하지 못할 때 나는 오류입니다.[^errors]

| 코드 | 뜻 | 흔한 원인 | 조치 |
|---|---|---|---|
| `InvalidConnection` | 연결이 끊어짐 · 삭제됨 · 만료됨 | 비밀번호 변경, MFA 재설정, 연결 삭제, 관리자의 제거, 연결이 없는 환경으로 가져옴 | 편집 화면에서 경고 카드를 골라 연결 변경 또는 새 연결 |
| `ConnectionNotConfigured` | 연결이 선택되지 않음 | 솔루션 가져오기에서 연결 참조 미지정, 연결 단계를 건너뜀, 값 없는 환경 변수 | 드롭다운에서 선택하거나 새로 만듦. 솔루션 흐름은 연결 참조 지정 |
| `Unauthorized (401)` | 인증 토큰이 잘못됐거나 만료됨 | OAuth 토큰 만료, 계정 비활성화 · 비밀번호 변경, 서비스 주체 비밀 만료, 조건부 액세스 차단 | 연결에서 연결 수정 후 다시 로그인 |
| `Forbidden (403)` | 인증은 됐으나 권한이 없음 | DLP 정책, 대상 리소스 권한 부족, 테넌트 수준 제한, 프리미엄 커넥터 | DLP · 대상 서비스 권한 · 라이선스 확인 |
| `ConnectionAuthorizationFailed` | 연결은 있으나 저장된 자격 증명이 무효 | 비밀번호 변경 · MFA 재설정, 90일 이상 쓰지 않아 refresh 토큰 만료, 관리자 동의 철회, 공유 연결 해제 | 연결 수정. 공유 연결은 소유자에게 요청 |

## 커넥터와 API 오류

대상 서비스가 돌려준 오류입니다.[^errors] 429 · 500 · 502 는 연결 문제 해결 문서에 있습니다.[^fixconn]

| 코드 | 뜻 | 흔한 원인 | 조치 |
|---|---|---|---|
| `ActionFailed` | 작업이 실패 상태를 돌려줌. 실제 내용은 출력 본문에 있음 | API의 4xx · 5xx, 하위 흐름 실패, 사용자 지정 커넥터의 응답 형식 | 출력에서 오류 메시지와 상태 코드 확인 |
| `BadRequest (400)` | 입력이 잘못되어 거부됨 | 형식 오류, 필수 필드 누락, 파일 이름 · 제목의 잘못된 문자, 길이 초과(SharePoint 한 줄 텍스트 255자) | 입력과 스키마 대조. `replace()` 로 문자 제거, `substring()` · `take()` 로 자름 |
| `NotFound (404)` | 대상이 없음 | 목록 · 라이브러리 · 사이트의 이름 변경이나 삭제, 폴더 · 채널 삭제, 고정 ID | 대상 확인 후 새 이름으로 변경. 고정 ID 대신 조회 사용 |
| `429 Too Many Requests` | 커넥터 호출 한도 초과 | 짧은 시간에 호출이 몰림 | 실패 작업 앞에 지연, 재시도 정책 설정. [C25](c25-throttling.html) |
| `500 Internal Server Error` | 대상 서비스 문제 | 서비스 장애 | 15~30분 뒤 재시도. Microsoft 365 서비스 상태 확인 |
| `502 Bad Gateway` | Power Automate와 대상 서비스 사이의 연결 실패 | 대개 일시적 | 작업의 재시도 설정. 계속되면 네트워크 · 방화벽 확인 |

## 트리거 오류

[C26](c26-trigger-conditions.html)의 트리거 조건에서 나는 코드입니다.[^errors]

| 코드 | 뜻 | 흔한 원인 | 조치 |
|---|---|---|---|
| `TriggerConditionNotMet` | 이벤트가 조건에 맞지 않아 실행을 시작하지 않음 | 항상 false인 식, 트리거 출력에 없는 필드 참조, 데이터가 조건과 다름 | 조건을 잠시 빼고 실행해 트리거 출력의 필드 이름과 값 확인 |

## 시간과 한도 오류

시간 제한이나 호출 한도를 넘을 때 나는 오류입니다.[^errors] 한도 값은 제한 문서를 따릅니다.[^limits]

| 코드 | 뜻 | 흔한 원인 | 조치 |
|---|---|---|---|
| `ActionTimedOut` | 작업이 설정된 시간 제한을 넘겨 취소됨 | 느린 외부 API, 승인 만료, 큰 파일, 너무 많은 행을 읽는 Dataverse 조회 | 작업 설정의 시간 제한 변경(ISO 8601. 5분은 `PT5M`) |
| `OperationTimedOut` | 오래 걸리는 작업이 최대 대기 시간을 넘김 | 콜백이 오지 않는 웹후크, 만료 없는 승인, 실행 시간 30일을 넘는 지연 | 시간 제한 명시. Run after 의 시간 초과 조건으로 갈래 추가. 30일이 넘는 일은 실행을 나눔 |
| `WorkflowRunActionRepetitionQuotaExceeded` | 각각에 적용의 항목 수 초과. 낮음 5,000 · 그 외 100,000 | 필터 없는 큰 목록, 중첩 반복 | 반복 전에 필터. 선택 · 배열 필터링으로 대체. 실행을 나눔 |
| `FlowRunQuotaExceeded` | 일일 작업 실행 한도 초과 | 반복이 많은 흐름 | 작업 수 줄임. 라이선스 변경. [C25](c25-throttling.html) |

## 라이선스 오류

| 코드 | 뜻 | 흔한 원인 | 조치 |
|---|---|---|---|
| `DirectApiAuthorizationRequired` | 프리미엄 커넥터를 쓰는데 호출자에게 프리미엄 라이선스가 없음 | Microsoft 365 라이선스로 실행, 소유자만 프리미엄, 예약 흐름 소유자의 라이선스 상실 | 오류 메시지에서 커넥터 이름 확인. 실행하는 사용자 또는 소유자에게 프리미엄 배정 |

인스턴트 흐름은 실행하는 사람의 라이선스가, 예약 · 자동화 흐름은 소유자의 라이선스가 기준입니다.[^errors]

## 연결이 끊어지는 원인

전에 돌던 흐름이 실패할 때 가장 흔한 원인은 연결입니다.[^fixconn]

| 원인 | 내용 |
|---|---|
| 비밀번호 변경 | 저장된 OAuth 토큰이 무효가 됨. 주기적 비밀번호 변경 정책 포함 |
| MFA 정책 변경 | 기존 토큰이 새 요구 조건을 충족하지 못함 |
| 관리자 동의 철회 | Power Automate가 서비스에 접근하는 앱 동의가 사라짐 |
| 토큰 만료 | 약 90일 쓰지 않으면 refresh 토큰 만료 |
| 서비스 주체 비밀 만료 | Microsoft Entra ID에서 새 비밀을 만들어 연결을 수정 |

다시 인증은 왼쪽 메뉴의 **연결**에서 합니다. 해당 연결의 점 세 개 메뉴에서 연결 수정을 고르고 로그인합니다. 다른 사람 소유의 공유 연결은 그 사람이 다시 인증하거나, 본인 연결을 만들어 흐름에 지정합니다.

여러 흐름이 동시에 실패하면 DLP 정책 변경을 의심합니다. DLP 변경은 예고 없이 즉시 적용됩니다. 흐름 세부 정보의 속성에 위반 메시지가 있으면 관리자에게 어떤 정책이 바뀌었는지 묻습니다.

운영 흐름에서 사용자 연결 대신 서비스 주체 연결을 쓰면 비밀번호 변경이나 퇴사의 영향을 받지 않습니다.

## 커넥터별 흔한 문제

| 커넥터 | 증상 | 원인 | 조치 |
|---|---|---|---|
| SharePoint | 처음 쓸 때 또는 정책 변경 뒤 403 | 관리자 동의 필요 | 관리자가 Microsoft Entra ID 엔터프라이즈 애플리케이션에서 동의 |
| SharePoint | 특정 사이트에서 403 | 사이트 권한 변경 | 최소 기여(Contribute) 권한 확인 |
| SharePoint | 목록 보기 임계값 초과 메시지 | 조회 결과가 5,000건 초과 | 필터 쿼리로 5,000건 미만으로 줄임. `$top` · 인덱스 열 사용 |
| SharePoint | 그 목록의 모든 작업에서 404 | 목록 · 라이브러리 이름 변경 | 새 이름이나 ID로 수정 |
| SharePoint | 성공했는데 값이 비거나 틀림 | 표시 이름과 내부 이름이 다름 | 내부 이름 사용. 열을 정렬할 때 URL에 보임 |
| Outlook | 공유 사서함에서 403 | 권한 없음 | 연결 소유자에게 Send As 또는 Full Access 권한 부여 |
| Outlook | 다른 사용자 사서함에서 401 | 대리자 권한 제거 | 권한 재부여 또는 공유 사서함 사용 |
| Outlook | MFA를 켠 뒤 401 | 토큰에 MFA 정보가 없음 | 연결 다시 인증 |
| Outlook | 큰 첨부에서 413 또는 실패 | 첨부 크기 제한 25MB | SharePoint · OneDrive에 올리고 링크 공유 |

## 실패 알림 메일

메일은 두 종류입니다.[^notify]

| 종류 | 보내는 때 | 담는 것 |
|---|---|---|
| 실행별 실패 경고 | 실패 직후. 원인이 알려진 문제일 때만 | 해당 실패와 고치는 단계 |
| 주간 오류 다이제스트 | 매주. 오류 유형과 관계없음 | 지난주의 모든 환경의 흐름 오류 요약. 일반 작업 실패 포함 |

실패 유형별 경고 메일 발송 여부입니다.

| 실패 유형 | 경고 메일 | 내용 |
|---|---|---|
| 끊어지거나 만료된 연결 | 보냄 | 다시 인증 필요 |
| 제한된 작업 | 보냄 | 커넥터 호출 한도 초과 |
| AI Builder 오류 | 보냄 | AI Builder 작업 실행 오류 |
| 데스크톱 흐름 오류 | 보냄 | 데스크톱 흐름 작업 실패 |
| 알려진 커넥터 오류 | 보냄 | 예: Outlook 작업의 잘못된 받는 사람 |
| 일반 작업 실패 | 보내지 않음 | 정해진 조치 없음. 실행 세부 정보 확인 |
| 계단식 오류 | 보내지 않음 | 앞 작업 실패로 함께 표시된 작업 |

받는 사람은 흐름 유형에 따라 다릅니다.

| 흐름 | 받는 사람 |
|---|---|
| 개인 흐름(공유 안 함) | 소유자(작성자)만 |
| 공유 흐름 | 소유자나 편집자로 공유된 모든 공동 소유자. 실행 전용 사용자 제외 |
| 솔루션 흐름 | Dataverse의 현재 소유자와 공동 소유자 |

환경 관리자와 테넌트 관리자에게는 보내지 않습니다.

경고 메일이 오지 않을 때의 확인 항목입니다.

| 원인 | 확인할 것 |
|---|---|
| 정해진 조치가 없는 실패 | 일반 작업 실패 또는 계단식 오류. 실행 기록에서 확인 |
| 쿨다운 기간 | 같은 흐름에 경고를 보낸 뒤 28일 동안 추가 경고 없음 |
| 경고가 켜져 있지 않음 | 모든 흐름에 기본으로 켜져 있지 않음. 흐름 설정 확인 |
| 흐름 삭제 | 실패 후 흐름이나 환경을 삭제하면 보내지 않음 |

모든 실패를 보려면 흐름 세부 정보의 실행 기록을 봅니다. 관리자는 Power Platform 관리 센터의 모니터 화면에서 흐름과 환경 단위로 봅니다.

복구 팁 메일의 구성입니다. 이 메일은 흐름 속성에서 끌 수 있습니다.[^fixflow]

| 항목 | 내용 |
|---|---|
| Time | 처음 실패한 시각 |
| What happened | 실패 원인 설명 |
| How do I fix | 해결 방법 |
| Troubleshooting tips | 실패 횟수와 같은 입력으로 다시 실행하는 링크 |

## 실패를 직접 알리는 구성

중요한 흐름은 실패 메일에만 의존하지 않고 흐름 안에 알림을 둡니다.[^fixconn]

| 순서 | 구성 |
|---:|---|
| 1 | 실패할 가능성이 큰 작업 뒤에 병렬 분기 추가 |
| 2 | 분기 첫 작업의 Run after 를 실패(has failed)만 선택 |
| 3 | 메일 보내기 또는 Teams 메시지에 흐름 이름과 오류 내용 작성 |

운영 흐름은 공유 사서함이나 Teams 채널로 받습니다. 주 1회 실행 기록에서 실패 · 취소 실행과 실행 수 급감을 확인합니다. Run after 와 범위는 [C17](c17-error-handling.html)에서 다룹니다.

## 샘플

흐름 `식 연습장_HGD` 를 씁니다. 없으면 [C7](c07-types.html)의 샘플로 만듭니다. 상수 식의 오류가 저장 단계에서 잡히는지 확인합니다. 실행 중 오류는 [C16](c16-run-history.html)의 샘플에서 확인합니다.

1. `식 연습장_HGD` 의 **편집**을 눌러 디자이너를 엽니다.
2. **작성** 카드를 누릅니다. **입력** 칸을 비우고 ***fx*** 단추를 누릅니다.

    식 편집기에 아래를 붙여넣고 **추가**를 누릅니다.

    ```
    int('abc')
    ```

3. **저장**을 누릅니다.

    **완료 기준**: 저장되지 않고 오류 메시지가 보인다.

4. **작성** 카드의 식을 아래로 바꾸고 **저장**을 누릅니다.

    ```
    div(100, 0)
    ```

    **완료 기준**: 저장되지 않고 오류 메시지가 보인다.

5. 없는 카드를 부르는 식으로 바꾸고 **저장**을 누릅니다.

    ```
    outputs('없는_카드')
    ```

    **완료 기준**: 저장되지 않고 오류 메시지가 보인다.

6. 실행할 수 있는 식으로 바꾸고 **저장**을 누릅니다.

    ```
    concat('A', 'B')
    ```

    **완료 기준**: 저장 완료 메시지가 보인다.
