## 선택기의 구조

선택기는 UI 요소가 화면의 어느 구성 요소인지 적은 글자입니다. `>` 왼쪽이 부모이고 오른쪽이 그 안의 자식입니다. 요소마다 `[특성="값"]` 을 하나 이상 붙입니다.[^build]

```
:desktop > window[Id="PxErpMain"][Process="PxErp"]
```

```
> body > main > form[Id="searchForm"] > input[Id="keyword"]
```

```
input[Id="keyword"]
```

| 표기 | 뜻 |
|---|---|
| `input` | 요소의 종류 |
| `[Id="keyword"]` | 특성 `Id` 값이 `keyword` |
| `[Id="PxErpMain"][Process="PxErp"]` | 두 특성이 모두 맞음 |
| `form > input` | form 안에 들어 있는 input |
| `:desktop` | 데스크톱 선택기의 뿌리 |

웹 선택기와 데스크톱 선택기는 구조가 같습니다. 쓸 수 있는 특성만 다릅니다. 웹은 HTML 특성을 쓰고, 데스크톱은 앱 설계에 따른 특성을 씁니다.[^build]

## 선택기 창

UI 요소 칸의 연필 아이콘이나 UI 요소 창의 **편집**으로 엽니다. 창 제목은 `"Input text 'keyword'" UI 요소 의 선택기` 모양입니다.[^lab5]

| 영역 | 하는 일 |
|---|---|
| 요소 목록 | 페이지나 창의 구조를 위에서부터 나열. 체크한 줄만 선택기에 들어감 |
| 특성 목록 | 고른 줄의 특성과 값. 체크한 특성만 선택기에 들어감 |
| 미리 보기 선택기 | 체크 결과로 만들어진 선택기 글자 |
| 선택기 테스트 | 지금 선택기로 화면에서 찾아봄 |
| 텍스트 편집기 | 선택기 글자를 직접 고침. 테스트도 여기서 됨 |

웹 요소에서 잡히는 특성은 `Class` · `Id` · `Ordinal` · `Title` 등이고, 창 요소에서 잡히는 특성은 `Id` · `Name` · `Process` 등입니다.[^lab5]

## 특성과 수준 고르기

특성이나 수준을 끄고 켜면 선택기가 가리키는 대상이 달라집니다.[^build] 고칠 때는 값이 변하지 않는 부분만 남깁니다.[^fail]

| 상황 | 고치는 방법 | 예 |
|---|---|---|
| 창 제목이 화면마다 바뀜 | `Name` 을 끄고 `Id` 를 켬 | `window[Id="PxErpMain"][Process="PxErp"]` |
| 값 끝의 숫자가 바뀜 | 연산자를 Starts with 로 바꾸고 앞부분만 둠 | `div[class^="some_class"]` |
| 상위 구조가 자주 바뀜 | 상위 수준의 체크를 끔 | `input[Id="keyword"]` |
| 같은 모양의 요소가 여럿임 | 상위 수준을 켜 경로를 넣음 | `> body > main > form[Id="searchForm"] > input[Id="keyword"]` |
| 글자는 그대로이고 구조가 바뀜 | 화면 글자로 찾음 | `a:contains("보이는 글자")` |

상위 요소를 많이 적을수록 같은 모양의 요소 사이에서 하나를 정확히 찾습니다. 그만큼 페이지 구조가 바뀌면 경로가 어긋납니다.[^lab5]

## 연산자

값 칸의 비교 방식을 바꿉니다. 정규식 엔진은 .NET 입니다.[^build]

| 연산자(영문판 이름) | 맞는 경우 | 값 `btn` 으로 `btnNext` 를 볼 때 |
|---|---|---|
| Equal to | 값이 똑같음 | 맞지 않음 |
| Not equal to | 그 값을 뺀 나머지 | 맞음 |
| Contains | 그 글자를 포함 | 맞음 |
| Starts with | 그 글자로 시작 | 맞음 |
| Ends with | 그 글자로 끝남 | 맞지 않음 |
| Regular expression match | 정규식에 맞음 | 식에 따라 다름 |

미리 보기 선택기에서 Equal to 는 `=`, Starts with 는 `^=` 로 보입니다.[^fail]

웹 선택기에 CSS 표현을 직접 적을 수 있습니다. 텍스트 편집기에 넣고 테스트로 확인합니다.[^lab5]

| 표현 | 2026-10-06 실측 결과 |
|---|---|
| `:eq()` | 동작함 |
| `:contains()` | 동작함 |
| `button[id="btnNext"]:not([disabled])` | 동작함 |
| `:visible` | 동작하지 않음 |
| `:not([style*="display: none"])` | 동작하지 않음 |
| 특성 목록의 `Disabled` 체크 | 동작하지 않음 |

## 변수 사용

값이 앞 작업의 결과에 따라 달라지면 값 칸에 `%변수%` 를 넣습니다. 직접 입력하거나 변수 단추로 고릅니다.[^build]

```
button[Id="%단추아이디%"]
```

```
:desktop > window[Name="%WindowName%"][Process="Notepad"]
```

시각 편집기에서 변수는 Equal to 연산자로만 씁니다. 다른 연산자와 변수를 함께 쓰면 시각 편집기 대신 텍스트 편집기에 선택기가 표시됩니다.[^ui]

## 여러 선택기와 순서

UI 요소 하나에 선택기를 여럿 둘 수 있습니다. 앞의 선택기가 실패하면 정의된 순서대로 다음 선택기를 씁니다.[^ui]

| 조작 | 위치 | 결과 |
|---|---|---|
| 재캡처 기능이 있는 선택기 | 선택기 창 단추 | 화면에서 다시 잡아 선택기를 추가 |
| 복사본 생성 | 선택기를 오른쪽 단추 | 같은 선택기를 복제 |
| 이름 바꾸기 | 선택기 이름을 오른쪽 단추 | 표시 이름 변경 |
| 사용 안 함 | 선택기를 오른쪽 단추 | 그 선택기를 건너뜀. 테스트할 때 씀 |
| 저장 | 선택기 창 | 모든 선택기의 변경을 한 번에 적용 |

선택기를 고쳐도 찾지 못할 때 쓰는 복구와 이미지 대체는 [P35](p35-selector-repair.html)에서 다룹니다.

## 텍스트 기반 선택기

구성 요소의 글자로 찾는 선택기입니다. 글자가 늘 같은 요소라면 구조가 바뀌어도 찾습니다.[^ui]

| 항목 | 내용 |
|---|---|
| 만드는 곳 | UI 요소 선택기에서 요소를 오른쪽 단추 › 텍스트에 따라 캡처. 기록기에서는 만들 수 없음 |
| 입력 칸 | 텍스트 값(변수 가능) · 연산자 |
| 쓰는 특성 | 데스크톱은 `Name`, 웹은 `Text`. SAP 은 `Text` |
| 조건 | 요소 자신이 글자를 가질 때만. 자식 요소에만 글자가 있으면 만들 수 없음 |

창 위에서 텍스트로 잡으면 기본 선택기가 만들어지고 `Name` 과 `Process` 특성이 들어갑니다.[^ui]

## 선택기 테스트

**선택기 테스트**는 지금 선택기로 화면에서 UI 요소를 찾아봅니다. 찾으려는 요소가 화면에 있어야 합니다.[^test]

| 결과 | 뜻 | 화면 표시 |
|---|---|---|
| 성공 | 요소를 찾음 | 실행할 때 다룰 요소를 강조 |
| 실패함 | 요소를 찾지 못함 | 찾지 못한 줄을 요소 목록에 강조 |
| 여러 UI 요소가 발견됨 | 요소가 둘 이상 | 실행할 때 다룰 요소를 강조. 화면 왼쪽 위에서 첫 요소 |

| 경우 | 조건 |
|---|---|
| 웹 요소 | 페이지가 열려 있고 웹 브라우저 탭 드롭다운에서 탭을 고름. 고르지 않으면 고르라는 창이 뜸 |
| 데스크톱 요소 | 부모 화면이 있어야 함. 없으면 화면 선택기 열기로 화면 선택기를 고침 |
| 변수가 든 선택기 | 테스트할 때 변수 값을 입력 |
| 선택기가 여럿 | 테스트 단추 옆 화살표 › 모든 선택기 테스트. 사용 안 함은 빠짐 |
| 고친 뒤 | 결과 아이콘이 사라짐. 다시 테스트 |

결과 아이콘을 누르면 세부 정보를 볼 수 있습니다.[^test]

## 모의 사이트의 id

모의 공고 사이트의 요소에는 id 가 붙어 있고 선택기가 이 id 로 찾습니다. id 를 바꾸면 선택기가 요소를 찾지 못합니다.

| 요소 | id | 있는 쪽 |
|---|---|---|
| 공고명 입력 | `keyword` | 모든 쪽 |
| 분류 | `category` | 모든 쪽 |
| 검색 단추 | `btnSearch` | 모든 쪽 |
| 결과 건수 | `resultCount` | 모든 쪽 |
| 결과 표 | `resultTable` | 모든 쪽 |
| 쪽 표시 | `pageInfo` | 모든 쪽 |
| 이전 단추 | `btnPrev` | 첫 쪽에는 없음 |
| 다음 단추 | `btnNext` | 마지막 쪽에는 없음 |

첫 쪽과 마지막 쪽에서는 해당 단추를 문서에서 지웁니다. 숨기기만 한 단추는 선택기가 그대로 찾습니다.[^lab5]

## 샘플

흐름 `개념 연습_HGD` 를 씁니다. 없으면 [P2](p02-types.html)의 1·2번으로 만듭니다.

1. Power Automate 콘솔에서 `개념 연습_HGD` 의 **편집**을 눌러 디자이너를 엽니다.
2. 작업 영역의 빈 곳을 한 번 누르고 `Ctrl` + `A` 를 누른 뒤 `Delete` 를 눌러 **Main** 의 줄을 지웁니다.
3. Edge 주소창에 아래 주소를 넣고 엽니다. 표 아래에 「1 / 4」가 보입니다. 이 창은 닫지 않습니다.

    ```
    {{ site.url }}{{ site.baseurl }}/practice/bid/
    ```

4. 작업 검색 칸에 `변수 설정` 을 입력하고 **변수 설정**을 작업 영역으로 끌어다 놓습니다. **변수**와 **값**에 아래를 차례로 넣고 **저장**을 누릅니다.

    ```
    단추아이디
    ```

    ```
    btnNext
    ```

5. 작업 검색 칸에 `Edge` 를 입력하고 **새 Microsoft Edge 시작**을 1번 줄 아래로 끌어다 놓습니다. **이니셜 URL**에 아래를 넣고 **저장**을 누릅니다.

    ```
    {{ site.url }}{{ site.baseurl }}/practice/bid/
    ```

6. 작업 검색 칸에 `버튼` 을 입력하고 **브라우저 자동화 › 웹 양식 채우기** 아래 **웹 페이지 버튼 누르기**를 2번 줄 아래로 끌어다 놓습니다.
7. **UI 요소** 드롭다운을 열고 **UI 요소 추가**를 누릅니다.
8. 3번의 Edge 창에서 **다음** 단추에 빨간 테두리와 `Button` 표시가 뜬 상태로 `Ctrl` + 왼쪽 클릭합니다.
9. **UI 요소** 칸 오른쪽 연필 아이콘을 눌러 선택기 창을 엽니다.

    **완료 기준**: **미리 보기 선택기**가 아래와 같다.

    ```
    button[Id="btnNext"]
    ```

10. **선택기 테스트**를 누릅니다. 탭을 고르는 창이 뜨면 `모의 공고 조회` 탭을 고릅니다.

    **완료 기준**: 결과가 성공이고 Edge 창의 **다음** 단추가 강조된다.

11. **특성** 목록에서 **Id** 체크를 풀고 **선택기 테스트**를 누릅니다.

    **완료 기준**: 결과가 여러 UI 요소 발견이고 **검색** 단추가 강조된다. 첫 쪽에는 단추가 **검색**과 **다음** 둘이고, 왼쪽 위의 **검색**이 실행할 때 눌릴 요소다.

12. **Id** 를 다시 체크하고 값을 아래로 바꾼 뒤 **선택기 테스트**를 누릅니다.

    ```
    btnNextX
    ```

    **완료 기준**: 결과가 실패이고 **요소** 목록의 그 줄이 강조된다.

13. 값을 아래로 바꾸고 연산자를 Contains 에 해당하는 항목으로 바꾼 뒤 **선택기 테스트**를 누릅니다.

    ```
    btn
    ```

    **완료 기준**: 결과가 여러 UI 요소 발견이다. `btnSearch` 와 `btnNext` 가 모두 맞는다.

14. 값을 아래로 바꾸고 연산자를 Starts with 에 해당하는 항목으로 바꾼 뒤 **선택기 테스트**를 누릅니다.

    ```
    btnN
    ```

    **완료 기준**: 결과가 성공이고 **다음** 단추가 강조된다. **미리 보기 선택기**에 `^=` 가 보인다.

15. 값을 아래로 바꾸고 연산자를 Ends with 에 해당하는 항목으로 바꾼 뒤 **선택기 테스트**를 누릅니다.

    ```
    Next
    ```

    **완료 기준**: 결과가 성공이고 **다음** 단추가 강조된다.

16. 값을 아래로 바꾸고 연산자를 Not equal to 에 해당하는 항목으로 바꾼 뒤 **선택기 테스트**를 누릅니다.

    ```
    btnNext
    ```

    **완료 기준**: 결과가 성공이고 **검색** 단추가 강조된다.

17. 값을 아래로 바꾸고 연산자를 Regular expression match 에 해당하는 항목으로 바꾼 뒤 **선택기 테스트**를 누릅니다.

    ```
    ^btn(Next|Search)$
    ```

    **완료 기준**: 결과가 여러 UI 요소 발견이다.

18. 연산자를 Equal to 에 해당하는 항목으로 바꾸고 값에 아래를 넣은 뒤 **선택기 테스트**를 누릅니다. 값을 묻는 창에 `btnNext` 를 넣습니다.

    ```
    %단추아이디%
    ```

    **완료 기준**: 결과가 성공이고 **다음** 단추가 강조된다.

19. 값을 `btnNext` 로 되돌리고 **저장**을 누릅니다.
20. 3번의 Edge 창에서 **다음**을 세 번 눌러 「4 / 4」 쪽으로 갑니다.
21. **UI 요소** 칸 연필 아이콘을 눌러 선택기 창을 열고 **선택기 테스트**를 누릅니다.

    **완료 기준**: 결과가 성공으로 나오지 않는다. 마지막 쪽에는 `btnNext` 가 문서에 없다.

22. 3번의 Edge 창에서 **이전**을 세 번 눌러 「1 / 4」 쪽으로 돌아옵니다.
23. 선택기를 오른쪽 단추로 누르고 **복사본 생성**을 고릅니다.
24. 첫 번째 선택기를 고르고 **Id** 값을 아래로 바꿉니다.

    ```
    btnNextX
    ```

25. **선택기 테스트** 옆 화살표를 누르고 **모든 선택기 테스트**를 고릅니다.

    **완료 기준**: 첫 번째 선택기는 실패, 두 번째 선택기는 성공이다.

26. 첫 번째 선택기를 오른쪽 단추로 누르고 **사용 안 함**을 고른 뒤 **모든 선택기 테스트**를 다시 고릅니다.

    **완료 기준**: 두 번째 선택기만 결과가 나온다.

27. 선택기 창의 **취소**를 누릅니다.
28. **UI 요소** 드롭다운을 열고 **UI 요소 추가**를 누릅니다.
29. 3번의 Edge 창에서 **다음** 단추에 빨간 테두리가 뜬 상태로 마우스 오른쪽 단추를 누르고 **텍스트에 따라 캡처**를 고릅니다.
30. **텍스트 값**이 `다음` 인지 확인하고 **캡처**를 누릅니다.
31. **UI 요소** 칸 연필 아이콘을 눌러 선택기 창을 엽니다.

    **완료 기준**: **미리 보기 선택기**에 `Text` 와 `다음` 이 들어 있고 **선택기 테스트** 결과가 성공이다.

32. 선택기 창의 **취소**를 누르고 대화 상자의 **취소**를 누릅니다.
