## 하위 흐름을 쓰는 때

하위 흐름은 다른 흐름이 부르는 흐름입니다. 단계가 많은 흐름을 나누거나 같은 일을 여러 흐름에서 쓸 때 만듭니다.[^child]

| 이점 | 내용 |
|---|---|
| 모듈화 | 재사용 구성 요소를 여러 흐름에 연결[^reuse] |
| 유지 관리 | 작은 흐름 단위로 수정과 문제 해결 |
| 확장 | 전체를 고치지 않고 구성 요소만 변경 |
| 제어 | 상위와 하위 사이에 데이터를 전달 |
| 협업 | 구성 요소별로 나눠 작업 |

문서의 예는 승인자 목록입니다. 프로젝트 제안 · 휴가 · 경비 흐름이 각각 하위 흐름을 불러 SharePoint 그룹의 승인자 목록을 받습니다.[^reuse]

흐름당 작업 500개와 중첩 8단계를 넘을 때도 하위 흐름으로 나눕니다.[^limits]

## 구성

| 항목 | 하위 흐름 | 상위 흐름 |
|---|---|---|
| 위치 | 같은 솔루션 | 같은 솔루션 |
| 트리거 | **수동으로 흐름 트리거** 필수 | 어떤 트리거든 가능 |
| 입력 | 트리거의 **+ 입력 추가** | **자식 흐름 실행** 작업의 칸에 값 입력 |
| 출력 | **Power App 또는 흐름에 응답**(Power Apps 커넥터) 또는 응답(프리미엄 HTTP 커넥터) | 작업 뒤의 동적 콘텐츠 |
| 연결 | 기본 제공 작업 · Dataverse 외의 커넥터는 내장 연결 필수 | 하위 흐름으로 연결을 넘길 수 없음 |

상위 흐름은 기본 제공 탭의 흐름 아래 **자식 흐름 실행** 작업으로 부릅니다. 고를 수 있는 흐름은 접근 권한이 있고 솔루션에 있으며 수동 트리거를 쓰는 흐름입니다.[^child]

내장 연결은 하위 흐름의 속성 페이지에서 정합니다. 실행 전용 사용자 타일의 편집에서 연결마다 실행 전용 사용자가 제공 대신 **이 연결 사용**을 고릅니다. 이 설정이 없으면 하위 워크플로가 내장 연결만 지원한다는 오류가 납니다.

동작과 조건입니다.

| 항목 | 내용 |
|---|---|
| 대기 시간 | 상위는 하위가 끝날 때까지 대기. 기본 제공 연결 · Dataverse만 쓰는 흐름은 1년, 그 외 30일[^child] |
| 응답 시간 | 응답 작업이 있는 흐름은 120초 안에 응답. 응답 뒤의 작업은 계속 실행[^limits] |
| 환경 이동 | 솔루션을 내보내 가져오면 상위와 하위가 자동으로 연결됨. URL 수정 불필요[^child] |
| 만드는 방법 | 상위와 하위를 같은 솔루션에서 직접 만듦. 솔루션으로 가져온 흐름은 예기치 않은 결과가 날 수 있음 |
| 라이선스 | 하위 흐름은 상위의 흐름 그룹 Process 용량을 상속하지 않음. 둘 다 그룹에 추가하고 각각 25개 한도에 포함 |
| HTTP로 부를 때 | HTTP 작업으로 부르면 트리거 URL 변경의 영향을 받음. **자식 흐름 실행**은 영향 없음[^trigger] |

## 초안과 버전

초안과 버전 기록은 솔루션 흐름에서 새 디자이너로 편집할 때만 씁니다. 저장 위치가 Dataverse이기 때문입니다.[^drafts] 솔루션 밖 흐름은 솔루션에 추가하면 버전이 생깁니다. 솔루션은 [C23](c23-solutions.html)에 있습니다.

| 조작 | 하는 일 | 조건 |
|---|---|---|
| **초안 저장** | 수정 내용을 저장. 오류가 있어도 저장됨 | 실행에는 반영되지 않음 |
| **게시** | 수정 내용을 실행에 반영 | 실행 가능한 상태여야 함 |
| **버전 기록** | 날짜별 버전 목록 표시. 최신 버전 · 게시됨 · 과거에 게시됨 표시 | 디자이너에서 염 |
| **복원** | 이전 버전을 최신 초안으로 복사 | 복원 후 게시해야 실행에 반영 |

흐름 제목 옆에 초안 또는 게시됨 상태가 보입니다.

버전 기록의 조건입니다.

| 항목 | 내용 |
|---|---|
| 보관 | 초안 6개월, 게시 버전 12개월(영어판) |
| 초안 테스트 | 불가. 게시해야 테스트 가능 |
| 메모 · 제목 | 추가 불가 |
| 버전 구분 | 타임스탬프. 정수 번호 없음 |
| 목록 필터 · 변경 요약 | 없음 |
| 버전 비교 | 나란히 비교 없음. 차례로 보거나 다른 탭에서 열어 비교 |
| 공동 소유자 | 모든 사용자의 전체 기록을 봄 |
| 내보내기 | 마지막 게시 버전만. 초안과 기록은 나가지 않음 |
| 흐름 URL | 솔루션에서 열면 버전마다 `workflowUniqueId` 가 바뀜. **내 흐름**에서 열면 `FlowId` 로 고정 |

데스크톱 흐름의 버전은 [P31](p31-version-share.html)에 있습니다.

## 샘플

솔루션 `개념 솔루션_HGD` 를 씁니다. 없으면 [C23](c23-solutions.html)의 샘플 1~3번으로 만듭니다. 이름을 받아 인사말을 돌려주는 하위 흐름과 그것을 부르는 상위 흐름을 만듭니다.

1. [Power Automate — {{ site.pa.environment }}]({{ site.pa.powerautomate_url }}){:target="_blank"}를 엽니다. 왼쪽 메뉴 **솔루션**에서 `개념 솔루션_HGD` 를 엽니다.
2. **신규** › **자동화** › **클라우드 흐름** › **인스턴트**를 누릅니다.
3. **흐름 이름**에 아래를 입력하고 트리거 목록에서 **수동으로 흐름 트리거**를 고른 뒤 **만들기**를 누릅니다. `HGD` 대신 본인 이니셜을 넣습니다.

    ```
    하위 흐름_HGD
    ```

4. 트리거의 **+ 입력 추가**를 누르고 **텍스트**를 고릅니다. 입력 이름 칸에 아래를 입력합니다.

    ```
    이름
    ```

5. 트리거 카드 아래 **+** › **작업 추가**에서 `응답` 을 검색해 **Power Apps** 아래 **Power App 또는 흐름에 응답**을 고릅니다.
6. **+ 출력 추가**를 누르고 **텍스트**를 고릅니다. 출력 이름 칸에 아래를 입력합니다.

    ```
    인사
    ```

7. 값 칸의 ***fx*** 단추를 누르고 아래를 붙여넣은 뒤 **추가**를 누릅니다.

    ```
    concat('안녕하세요, ', triggerBody()?['text'])
    ```

8. **초안 저장**을 누르고 **게시**를 누릅니다.
9. 솔루션으로 돌아가 **신규** › **자동화** › **클라우드 흐름** › **인스턴트**를 누릅니다. **흐름 이름**에 아래를 입력하고 **수동으로 흐름 트리거**를 고른 뒤 **만들기**를 누릅니다.

    ```
    상위 흐름_HGD
    ```

10. 트리거 카드 아래 **+** › **작업 추가**에서 `자식 흐름` 을 검색해 **흐름** 아래 **자식 흐름 실행**을 고릅니다. **하위 흐름**에서 `하위 흐름_HGD` 를 고릅니다.
11. **이름** 칸에 아래를 입력합니다.

    ```
    HGD
    ```

12. **자식 흐름 실행** 아래 **+** › **작업 추가**에서 `작성` 을 검색해 **작성**을 고릅니다. **입력** 칸의 번개 단추를 누르고 **자식 흐름 실행** 아래 **인사**를 고릅니다.
13. **초안 저장**을 누르고 **게시**를 누릅니다.
14. **테스트** › **수동** › **테스트**를 누릅니다. **흐름 실행**을 누르고 **완료**를 누릅니다.
15. 실행 화면에서 **작성** 카드를 누릅니다.

    **완료 기준**: 출력이 `안녕하세요, HGD` 이다.

16. 실행 화면 오른쪽 위 **편집**을 눌러 디자이너로 돌아옵니다. **버전 기록**을 누릅니다.

    **완료 기준**: 버전 기록 패널에 게시됨으로 표시된 버전이 보인다.
